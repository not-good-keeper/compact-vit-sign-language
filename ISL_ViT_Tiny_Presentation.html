Problem Statement, Introduction & Motivation

4 marks

Problem statement

Indian Sign Language is the primary language of roughly 63 million people with hearing impairment in India, and almost no hearing person understands it. Automatic ISL recognition must therefore run on a wearable device, on ordinary video, and be accurate enough on unseen signers to be relied on — a condition existing benchmarks do not test.

Domain & application

  • Domain: vision-based isolated sign language recognition (ISLR) — the classification building block of a continuous recognition system.
  • Application: a smart-glasses assistant that reads a sign and renders it as text or speech for a hearing listener.
  • Constraint: wearable compute — a few megabytes of weights and a few milliseconds per clip.

Existing limitation this work addresses

Published ISL systems report 94–99 % accuracy, but on random splits in which clips of the same signer, recorded in the same session, appear in both training and test sets. That number does not predict performance on a new signer.

Why a tiny factorised ViT is the appropriate approach. Transformers model long-range spatial and temporal structure, which sign language needs (handshape + motion + location). But with ~11 training clips per class a full-frame video transformer memorises the room. Cropping to three anatomical streams and factorising attention over space then time cuts the attention cost ~48× and removes background and signer identity from the input entirely.

Measured leakage decomposition

random-videoNear-duplicate takes and shared sessions98.5 %

Algorithm Procedure — Step by Step

5 marks

1 · Input

V ∈ ℝ^{F×H×W×3}, label y ∈ {1..C} F ≈ 50-120 frames, C = 50

2 · Preprocessing — temporal sampling

eₖ = k·F/T , k = 0..T tₖ = ⌊eₖ + uₖ(eₖ₊₁ − eₖ)⌋ uₖ ~ U(0,1) train uₖ = ½ eval

3 · Detection & crop

b_{t,s}, σ_{t,s} = Detect(V[tₖ]) x_{t,s} = (resize(V[tₖ], b_{t,s})/255 − μ)/σ x_{t,s} ∈ ℝ^{64×64×3}, s ∈ {L,R,F}

4 · Patch / token formation

x_{t,s} → {p₁..p₁₆}, pⱼ ∈ ℝ^{16·16·3} non-overlapping 16×16 patches

5 · Embedding + positional encoding

z⁰_{t,s} = [x_cls ; E·p₁ ; .. ; E·p₁₆] + E_pos E ∈ ℝ^{768×192}, E_pos ∈ ℝ^{17×192}

6–9 · Transformer block (Stage A, ℓ = 1..4)

Attention Q = z W_Q , K = z W_K , V = z W_V A = softmax( Q Kᵀ / √d_h ) head_i = A·V , d_h = d/h = 64 MHSA(z) = [head₁;head₂;head₃] W_O Residual + norm z′ = z + DropPath( MHSA( LN(z) ) ) MLP MLP(z) = GELU(z W₁ + b₁) W₂ + b₂ W₁ ∈ ℝ^{192×768}, W₂ ∈ ℝ^{768×192} z = z′ + DropPath( MLP( LN(z′) ) )

Descriptor + geometry injection PROPOSED

g_{t,s} = W_g·[cx, cy, √(w·h)] + W_r·𝟙[σ_{t,s} ∈ {direct, roi}] h_{t,s} = z⁴_{t,s}[cls] + g_{t,s} ∈ ℝ^{192}

Stage B input

f_t = W_f·[h_{t,L} ; h_{t,R} ; h_{t,F}] + E_time[t] W_f ∈ ℝ^{192×576} u = TemporalViT(f₁..f_T) same block form

10 · Classification

ū = (1/T) Σ_t u_t ŷ = softmax( W_c·LN(ū) + b_c ) W_c ∈ ℝ^{50×192}

11 · Loss

mixup on the batch λ ~ Beta(α,α), α = 0.2 x̃ = λxᵢ + (1−λ)xⱼ , ỹ = λyᵢ + (1−λ)yⱼ label-smoothed cross-entropy, ε = 0.1 ℒ = − Σ_c [(1−ε)·ỹ_c + ε/C] · log ŷ_c floor: for C=50, ε=0.1 → min ℒ = 0.702

12 · Backpropagation

g_θ = ∂ℒ/∂θ reverse-mode autodiff g_θ ← g_θ · min(1, γ/‖g_θ‖₂), γ = 1.0 gradient clipped by global norm

13 · Parameter update (AdamW)

m ← β₁m + (1−β₁)g , β₁ = 0.9 v ← β₂v + (1−β₂)g² , β₂ = 0.999 m̂ = m/(1−β₁ᵗ) , v̂ = v/(1−β₂ᵗ) θ ← θ − η(s)·( m̂/(√v̂+ϵ) + wd·θ ) η(s) = η₀·½(1+cos(π(s−s_w)/(S−s_w))) encoder LR = 0.1 × head LR θ_EMA ← β θ_EMA + (1−β)θ , β = 0.99

14–15 · Inference & output

p̄ = (1/|M||V|) Σ_{m,v} softmax(f_m(x^{(v)})) V = 3 phases × 2 flips = 6 views output = argmax p̄ if max p̄ ≥ τ ABSTAIN otherwise (τ = 0.4)

Inference & discussion

  • +24 points came entirely from data handling — training length, frame count, cache depth, test-time averaging. The architecture never changed.
  • More data can be worse data. Adding 76 labelled CISLR clips cost 5.7 points, because the detector finds a left hand in 25 % of CISLR frames against 91 % in INCLUDE.
  • Lower loss is not better features. The 16-frame SSL pretrain reached a lower reconstruction loss and transferred 10 points worse — it had no temporal jitter and optimised a shortcut.
Limitations. (i) Cross-corpus transfer is ~1 %, at chance — every number here is INCLUDE-to-INCLUDE. (ii) Session-disjoint is a proxy for signer-independence; INCLUDE ships no signer IDs. (iii) 50 words, not 262 (42.1 % on the full vocabulary). (iv) Isolated words only — no continuous signing or translation. (v) No evaluation on self-recorded footage yet.

Preprocessing chain

Sample 32 frames uniformly → letterbox to 720×1280 → MediaPipe two-stage detection → crop 3 streams at 128 px → memmap cache. At training time: sample 16 of 32, random-resized crop to 64 px, horizontal flip with stream swap, colour jitter, grayscale, stream dropout, resolution jitter.

It is published on Zenodo at zenodo.org/records/4010759, with the source paper at ACM Multimedia 2020. IEEE Dataport hosts other, different ISL datasets (e.g. “Indian Sign Language dataset ISL-50”). Cite the real Zenodo URL and note the discrepancy, or clear a substitution with the faculty. Do not invent a Dataport link.

Why INCLUDE is suitable

  • Largest openly available ISL word-level corpus, recorded with experienced signers in conditions close to natural use.
  • 263 words across 15 semantic categories allows a vocabulary-size study, which turned out to matter more than any architecture change.
  • Filenames retain the camera's MVI_#### counter — the only handle available for reconstructing recording sessions.

Project-specific novelty in dataset use

  1. Session-disjoint protocol from camera metadata. INCLUDE ships no signer IDs, so signer-independence is not directly constructible; sessions are recovered by clustering on the counter and whole blocks held out.
  2. Leakage decomposition separating near-duplicate takes from shared sessions.
  3. Vocabulary tiers ranked by total clips with a floor on held-out clips — ranking by training support produced a 30-word tier with 22 test clips in total.
  4. A cache deeper than the model consumes (32 stored, 16 used).
  5. A leak guard that re-reads the written split file and asserts no held-out cross-corpus clip reached training.
Honest framing for the panel. Session-disjoint approximates signer-independence; it does not guarantee it. The surveyed dataset papers (Isharah, TSL-ONE-S, Greek SL corpus) all ship explicit signer partitions — that is the standard this field is moving toward, and INCLUDE predates it.

Why this is the standard reference for this application

  1. Same language, same architecture family, same deployment claim. A hybrid CNN + ViT for Indian Sign Language targeting real-time use — the closest published system to ours on all three axes, which makes it a genuine baseline rather than a loose citation.
  2. Peer-reviewed in a Q1-tier venue within the required window (Scientific Reports, 2025), so it satisfies the rubric without an exception.
  3. It sets up our contribution by contrast. They report 97.5 % under optimised conditions. We reproduce that class of number (98.5 %) with a random split and then show the same model scores 75.6 % session-disjoint. Our contribution — quantifying and then closing the protocol gap — is only legible against a strong published claim.
  4. It shares our end goal. Both target continuous ISL understanding for a real user, not isolated-word classification as an end in itself, so its system design is the right template for our roadmap.
